\section{The complete audit record}\label{app:audit}
The full reimplementation audit is separate from the earlier revision's
54-certificate replay. Its raw outputs remain in
\begin{quote}\small\raggedright
\path{checks/independent-review-20261026/}.
\end{quote}
A frozen, organized copy is provided at
\begin{quote}\small\raggedright
\path{review/audits/20261026-full-replay/}.
\end{quote}
Paths here are relative to the research root. The organized package
contains 372 original audit files copied byte for byte, the adopted
parent and terminal indexes, a joined per-leaf audit ledger, and new
reproduction instructions. Packaging these records is distinct from
running the audit again.

\subsection{Source provenance and implementation checks}
The new checker is \path{RupAudit.cs}; its SHA-256 is
\begin{center}\small\ttfamily

\end{center}
The displayed lines are concatenated without the final punctuation.
The full audit uses this checker, not the experimental
\path{RupAuditRoot.cs} variant, which is retained only as a separate trial.
The original audit environment was Windows 11, Python 3.13.0, and the
Microsoft .NET Framework C\# compiler. No SAT library was imported by
the new auditor or checker. The main enumerations and replays are
deterministic; seed 20261026 applies only to the 150 comparison tests.

One source-provenance detail is recorded explicitly. The input-audit
process started with the source now saved as \path{review-initial.py}.
While it ran, only the count-list comparison in a different function,
\texttt{local\_math}, was corrected: the initial test had confused the
representative-selection key with the list's serialization order.
The input-audit report read its source hash from disk at process exit,
so that field identifies the corrected file rather than the file loaded
at process start. Both snapshots are retained. A subsequent syntax-tree
comparison confirms that \texttt{inputs} and all its helpers are identical
between them. The discrepancy is a provenance issue in the report, not
an omitted input check; it should not be concealed by rewriting the old
report's hash.

\subsection{Reproduction with new output directories}
The organized package's \path{tools/verify_package.py} checks its own
file inventory and hashes and the recorded audit totals. It does not
recheck mathematical inferences. The separate \path{tools/replay.py}
accepts an explicit research-root directory and a fresh output directory,
recompiles the preserved checker, checks selected input/proof hashes,
and passes the actual files to it. It records new compiler output,
commands, fingerprints, per-leaf results, and a scope-limited report.
Its \texttt{--full} option selects all leaves; weight, profile, and limit
options permit smaller checks whose reports remain explicitly limited.
The original run files and batch paths are preserved as historical data.

The compact audit package contains code, tests, reports, hashes, and
evidence indexes. The 6,585,642,510 bytes of terminal CNF and proof files
remain in the research archive at the indexed relative paths. They are
required for proof replay and are not embedded in the compact package
or the manuscript source archive. Hash matching alone establishes
integrity, not the correctness of the mathematical argument.
