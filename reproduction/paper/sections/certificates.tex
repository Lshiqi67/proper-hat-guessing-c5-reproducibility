\section{Refutations and the recorded finite verification}\label{sec:certificates}
The reductions now specify a finite list of formulas. A solver searches
for refutations, but its reported status alone is not the evidence used
here. Each adopted proof is a sequence of clauses checked by a separate
program using the elementary rule below.
\subsection{The inference rule checked}
A literal is a Boolean variable or its negation, and a clause is a
disjunction of literals. Given a set of clauses $D$, unit propagation
repeatedly sets the sole unassigned literal of a clause to true when all
its other literals are false. An empty clause or conflicting unit
assignments produce a contradiction.
For example, from $(p\lor q)$ and $\neg p$, assuming $\neg q$ forces
$p$ and then a conflict. Hence the unit clause $q$ has the RUP property
defined below. For an empty added clause there are no assumptions: the
retained database must itself produce a unit-propagation conflict.

\begin{definition}
A clause $C=\ell_1\lor\cdots\lor\ell_k$ has the
\emph{reverse-unit-propagation} (RUP) property with respect to $D$ if unit
propagation on
\[
D\land\neg\ell_1\land\cdots\land\neg\ell_k
\]
produces a contradiction. The same definition applies when $C$ is empty.
\end{definition}

\begin{lemma}[Soundness of RUP checking]\label{lem:rup}
If $C$ is RUP with respect to $D$, then $D\models C$. Starting from a
formula $F$, any sequence of RUP additions and deletions that reaches a
checked empty clause proves that $F$ is unsatisfiable, provided all clauses
used in each check are original clauses or previously verified consequences
of $F$.
\end{lemma}
\begin{proof}
Every assignment satisfying a unit clause must make its unique remaining
literal true. Induction over propagation steps shows that a satisfying
assignment of $D\land\neg C$ would have to obey all propagated units. It
cannot obey a contradictory pair or satisfy an empty clause. Hence
$D\land\neg C$ is unsatisfiable and $D\models C$.

Inductively, every retained clause is a consequence of $F$. A newly
accepted clause follows from some retained consequences of $F$, so it too
is a consequence of $F$. Deleting clauses preserves this invariant. A
checked empty clause therefore implies $F\models\bot$.
\end{proof}

This is a standard clausal proof mechanism; see~\cite{drat} for the wider
DRUP/DRAT setting. The checks used here accept only RUP additions, not
general RAT additions. They are custom local implementations, not an
execution of the external DRAT-trim program.

In the original verification, the fast checker permanently retains original input clauses and
processes deletion records for learned clauses. When it rejects a
certificate, a second checker starts from the original input, ignores all
deletions, and checks every addition anew. Either accepted execution is
sound by Lemma~\ref{lem:rup}: retaining previously established consequences
cannot introduce an unjustified premise. A rejected addition is never
skipped. Parser checks require valid variable ranges and clause terminators for
the input and all additions, the declared input clause count, and a
checked empty clause. The deletion-ignoring checker skips deletion records;
it does not validate their literal lists. This does not affect its
inference argument: a deletion record neither adds a premise nor removes
an obligation to check an addition.

\subsection{The finite assertion and its local evidence}
\begin{proposition}[Finite exclusion by computation]\label{prop:finite}
For every $17\leq n\leq25$ and $a\in\calR_n$, either the parent
$F_a$ has a RUP refutation, or all 51 formulas $F_{a,t}$, $t\in\calT$,
have RUP refutations. The associated input-extension and coverage checks
described above pass for the recorded inputs.
\end{proposition}

\begin{proof}[Recorded computational verification]
The two enumeration schemes following~\eqref{eq:inverse} produce identical
representative lists. The Boolean inputs are checked as in
Proposition~\ref{prop:input}. Refutations are generated by Glucose3
through PySAT, then read from disk and checked using the separate RUP
implementations. The later complete audit replays all terminal refutations
with \texttt{RupAudit}, checking every addition and the final empty
clause afresh. It also rechecks input preservation using a new
standard-library auditor. Table~\ref{tab:counts} gives the complete
branch counts and accepted addition counts. The full certificate files,
input lists, source fingerprints, and audit reports are retained in the
local research archive described in Appendix~\ref{app:reproduction}.
These original and subsequent checks supply the computational component
of the argument. The external-review and software-verification limitations
stated in the introduction continue to apply.
\end{proof}

\subsection{Limits, failures, and the scope of the evidence}
The initial searches at weights 24 and 25 used a budget of 100,000
conflicts per parent and left 36 and 69 parents undecided. Each was then
refined into all 51 patterns, with a budget of 300,000 conflicts per
subcase. The final refutations cover every such subcase. Other weights
also used refinement for selected difficult or large-certificate parents.
A budget exhaustion, an abnormal solver exit, or an unverified
\texttt{UNSAT} status is not used as an exclusion.

In the original audit, the accepted deletion-ignoring fallback was used for 129 terminal
certificates at weights 22--23 and 296 at weights 24--25. Those counts
refer to full replays, not omitted proof lines. Separate comparisons with
simple propagation implementations are retained in the archive, but
finite implementation tests are not a proof-assistant verification of
the checker.

The complete evidence manifest records 30,110 files totaling
6,617,692,938 bytes, with SHA-256 hashes. These figures concern the
selected evidence files, not every historical output in the workspace.
Hash equality establishes file integrity, not mathematical correctness.
Some final audit passes reused already checked terminal certificates only
when the input, proof, and checker hashes matched. The records distinguish
such reuse from a fresh replay. In particular, no reported final-pass
runtime should be interpreted as the time for an independent reproduction
from scratch.


\subsection{Complete audit with reimplemented checkers}\label{sec:full-audit}
The later audit completed on October 26, 2026, at 21:38:40 in
UTC+08:00. It read the adopted CNF and proof files directly, without
using old successful-check caches. All 8613 terminal proofs passed,
with 66,403,934 verified additions and a checked empty clause for each
input. The per-leaf identifiers were matched to the complete terminal
list with no missing or duplicate leaf, and the addition counts agree
with Table~\ref{tab:counts} at every weight.

The new Python auditor checked all 1413 parent inputs and all 7344
refined child inputs against the game and branch definitions. It checked
14 actual component types on all 65,399 valid input assignments and
evaluated every component clause on each constructed auxiliary
assignment. It also matched hashes for the 17,226 terminal CNF and proof
files, totaling 6,585,642,510 bytes. This file set excludes the extra
metadata counted in the older 30,110-file manifest.

The new checker first retains every original clause and processes
deletions of learned clauses. If an addition fails this check, it
restarts from the original input and ignores all deletions; it never
skips a rejected addition. Its parser validates input and proof literal
ranges and terminators, including deletion records, checks the declared
input clause count, and requires the final checked empty clause.
The inference invariant is precisely Lemma~\ref{lem:rup}.

There were 449 full fallbacks: 24 at weights 19--21, 129 at weights
22--23, and 296 at weights 24--25. In the original verification,
weights 17--21 used the deletion-ignoring checker directly, so no
corresponding preliminary fallback count was reported. The new total
therefore does not contradict the earlier figures.

The audit also checked 6561 endpoint-function pairs, 1440 tight-support
cases, the full count classification, all 1024 diagonal words, all 24
permutations of the non-special colors, and all 10 graph automorphisms.
It directly verified the four-color formula on all 240 proper colorings
and the displayed local witness on all 1020 five-colorings. The new
checker passed 150 seeded comparisons with a simple propagation
implementation and 20 deterministic boundary or resolution tests.
These are finite implementation checks, not a formal correctness proof
of the checker. No new SAT search was needed for this audit.
